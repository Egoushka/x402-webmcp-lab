How it works

Ask, get a 402, sign, done.

Agent hostholds the wallet and the spending caps
calls get_quote over WebMCP
Web pageregisters the tool with document.modelContext
fetch /api/quote gets 402 + price
Wallet bridgehost signs an EIP-3009 authorization (2.1 ms)
retry with PAYMENT-SIGNATURE
Merchant + facilitatorverify, settle on chain, return 200 + result

The page never holds a key.

Real vs test

What is real, what is pretend.

Real

  • Chromium 158.0.8127.18 with native WebMCP
  • Official x402 SDK 2.30.0
  • EIP-712 signing, on-chain transfer
  • Spend caps and replay protection

Test

  • Local ganache chain
  • Own test token, not USDC
  • Facilitator runs on loopback
  • A script, not an LLM
  • The wallet bridge is my own hack

A hosted facilitator and a real RPC add round trips I did not measure.

The open problem

Who holds the agent's wallet?

WebMCP has no wallet hook. The page can ask for money. Somebody else has to sign. I do not know who yet.

  • The browser
  • The model vendor
  • You

Every demo I found keeps the key in the page or its server.
